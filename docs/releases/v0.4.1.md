# TraceForge v0.4.1 — Public Beta

TraceForge `v0.4.1` is an **Experimental Beta**. Replay Capsule schema `0.1.0` and Capture Event schema `0.2.0` remain independent contracts.

## What is TraceForge?

TraceForge is local-first replay and regression infrastructure for Python AI agents. It turns controlled, sanitized executions into sealed evidence that can be validated, replayed offline, compared, evaluated against developer-approved expectations, and exported as pytest.

## What's included

- CLI and Python package;
- explicit capture with best-effort redaction;
- immutable Replay Capsule sealing and validation;
- deterministic exact replay, comparison, regression evaluation, and pytest export;
- controlled weather, RAG citation-grounding, and tool-argument/HTTP cases;
- local FastAPI replay workbench and SQLite history;
- optional Go/Kafka/Python distributed capture path; and
- bounded Docker Compose, kind/Kustomize, and local Terraform development assets.

## Replay core

Exact replay freezes recorded model and HTTP outcomes and matches them by sequence and sanitized request fingerprint. Missing, extra, reordered, or mismatched fixtures fail closed. Regression specifications remain separate from immutable capsule evidence, so technical completion and behavioral correctness are evaluated independently.

Fork replay and fresh-model replay are not included.

## Distributed capture path

The optional local path is:

```text
Go ingestion gateway
  -> Kafka topic traceforge.capture.v1
  -> Python assembly worker
  -> SQLite event-id deduplication and ordered assembly
  -> sealed Replay Capsule
  -> replay/regression core
```

Kafka processing is at least once with domain idempotency; this release does not claim exactly-once delivery. The DLQ boundary commits a source offset only after its DLQ publish succeeds.

## Observability

The local distributed path includes W3C trace-context propagation, optional OpenTelemetry capture spans, separate linked replay traces, and bounded Prometheus metrics. It does not include a searchable trace store, production dashboard, alerting/SLO system, or Kafka consumer-lag metric.

## Verification

Release evidence covers the existing Python and Go suites, lint/format checks, package building and installed CLI smoke tests, Docker Compose parsing, Kustomize rendering/ownership checks, Terraform formatting/static tests, and repository hygiene. Exact commands, results, environment, revision, and limitations are recorded in the [verification ledger](../verification-ledger.md).

## Known limitations

- Capture is controlled and framework support is bounded, not arbitrary Python/LangGraph instrumentation.
- Recorded model and HTTP outcomes exist; there is no generic tool dependency contract.
- Fork replay, fresh-model replay, and richer execution diffing remain planned.
- Redaction is best effort and the process-wide network guard is not an OS sandbox.
- SQLite is local and single-writer; there is no distributed searchable trace store.
- There is no hosted service, authentication, multi-tenancy, high availability, production Kubernetes/cloud Terraform, or production security claim.
- No repeatable benchmark suite establishes throughput, latency, capacity, or reliability claims.
